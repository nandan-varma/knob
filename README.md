# Knob

A native macOS 26+ (Tahoe) distraction blocker. Block apps and websites via a menu bar app, with quick sessions, recurring schedules, strict mode, and a stats dashboard.

Swift 6 + SwiftUI, deployment target macOS 26.0.

## Setup

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` — never hand-edit `Knob.xcodeproj`.

```bash
xcodegen generate
```

Run this after editing `project.yml`, or after adding/removing source files in a way that changes directory structure. Plain new `.swift` files inside an already-listed folder don't need it — XcodeGen globs by folder.

## Build

```bash
# Compile-only check (fast, no signing needed) — use this while iterating on source changes
xcodebuild -project Knob.xcodeproj -scheme Knob -configuration Debug \
  -destination "platform=macOS" build CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO

# Full signed build (needed to actually run it, since AppBlocker/SessionManager require
# a running, launched app rather than just compiled code)
xcodebuild -project Knob.xcodeproj -scheme Knob -configuration Debug \
  -destination "platform=macOS" build -allowProvisioningUpdates

# Run the built app
open ~/Library/Developer/Xcode/DerivedData/Knob-*/Build/Products/Debug/Knob.app
```

`xcodebuild` run from a plain shell needs an Xcode account already signed in via the Xcode GUI (Settings > Accounts).

No test target exists. No lint config (SwiftLint/SwiftFormat) is set up.

## Current limitation: website blocking is inert

Apple gates the NetworkExtension content-filter sub-capability behind a manual support request beyond the standard "Network Extensions" App ID checkbox. That request is pending for this team, so `com.apple.developer.networking.networkextension` and `com.apple.developer.system-extension.install` are currently removed from both entitlements files (see the `# TEMPORARY` comments in `project.yml`).

Until Apple approves it, the app builds and runs with **app blocking only** — the website-filter system extension embeds but can't activate.

## Architecture

See `CLAUDE.md` for the full architecture writeup, including why this isn't built on Apple's `FamilyControls`/`ManagedSettings`/`DeviceActivity` stack (those frameworks don't exist for macOS apps, despite shipping in the macOS SDK).

Short version:

- **App blocking** (`Knob/Blocking/AppBlocker.swift`): `NSWorkspace` launch-notification monitoring + termination. Only works while Knob is running, which is why it's meant to run as a login item.
- **Website blocking** (`KnobFilterExtension/`, `Knob/Blocking/WebFilterController.swift`): a `NEFilterDataProvider` packaged as a macOS System Extension.
- **Quick sessions and recurring schedules** (`Knob/Blocking/SessionManager.swift`): in-app timers, since there's no `DeviceActivity`-style OS scheduler on macOS.
- **Shared state**: an App Group (`group.com.nandanvarma.knob`) — SwiftData (`Shared/SharedModelContainer.swift`) for the main app's data, plus a minimal `UserDefaults`-backed active block list (`Shared/ActiveBlockList.swift`) for the sandboxed filter extension.
